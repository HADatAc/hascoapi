# HASCOAPI Endpoint Documentation

This document provides a comprehensive guide to the HASCOAPI endpoints, generated by inspecting the API's route table. The purpose of each endpoint is described in plain English to facilitate understanding and usage. This documentation is intended to help clarify the functionality of the HASCOAPI for developers, explaining key concepts and detailing the available operations.

## Core Concepts

To effectively use the HASCOAPI, it's important to be familiar with the following concepts, which are central to the system's design and functionality.

### Element Types (`elementType`)

Many endpoints include an `{elementType}` parameter in their path. This parameter specifies the type of data structure being accessed or manipulated, based on the HASCO (Human-Aware Science and Collaboration Ontology). Each element type corresponds to a specific class in the ontology and has a unique identifier used in API calls.

Here are some of the key element types:

- **`study`**: The central organizing entity, representing a research study.
- **`studyobjectcollection` (SOC)**: A collection of objects that share a common superclass. These can be collections of domain objects (e.g., samples derived from an entity of interest like a human subject or a water tap), temporal objects (e.g., time intervals, instants, timestamps like `birthtime`), or spatial objects (e.g., locations, addresses, geographical regions).
- **`studyobject`**: An individual object within a Study Object Collection.
- **`virtualcolumn` (VC)**: Represents a variable or data column in a dataset, linked to a study.
- **`datafile`**: A record representing a physical data file (e.g., a CSV or XLSX file). DataFiles are closely related to Metadata Templates (MTs), as each MT generated or ingested is presented as content within a DataFile.
- **`dsg` (Data Stream Generator)**: A metadata template that defines the structure and content of a data stream, linking raw data to the semantic model.
- **`sdd` (Semantic Data Dictionary)**: A metadata template that defines the semantics of data variables.
- **`instrument`**: A data collection instrument. This can be a questionnaire or survey, but can also represent a physical instrument with internal detectors (sensors) and actuators, which may be grouped by logical controllers.
- **`deployment`**: The placement of an instrument and its components at a platform, offering the instrument the conditions for it to be operational (collecting and/or receiving data).
- **`stream` / `streamtopic`**: Entities related to managing real-time or streaming data. Streams are source of data and they can be datafile streams or message streams.
- **`agent`**, **`person`**, **`organization`**: Entities for representing actors and provenance.
- **`attribute`**, **`unit`**: Entities for describing semantic variables.

### Metadata Templates (MTs) & The Ingestion Workflow

A critical function of HASCOAPI is the ingestion of data from structured spreadsheet files known as Metadata Templates (MTs). This process transforms tabular data into semantic triples in the knowledge graph.

The ingestion process follows a specific three-step workflow:

1.  **Create the DataFile Entity**:
    -   A `POST` request is made to an endpoint like `/api/dsg/create/{json}`.
    -   This step doesn't upload the file itself but creates the initial `DataFile` and `DSG` entities in the triplestore. It returns the URI of the newly created `DataFile`.

2.  **Upload the Physical File**:
    -   A `POST` request is made to `/api/uploadFile/{elementuri}/{filename}`.
    -   `{elementuri}` is the URI of the `DataFile` entity created in Step 1.
    -   `{filename}` is the name of the `.xlsx` or `.csv` file being uploaded.
    -   The request body contains the binary data of the file.

3.  **Trigger Ingestion**:
    -   A `POST` request is made to `/api/ingest/{status}/{elementType}/{elementUri}`.
    -   `{elementUri}` is the URI of the `DataFile` from Step 1.
    -   This initiates the asynchronous process of parsing the uploaded file and creating all the corresponding entities (Studies, Study Objects, Virtual Columns, etc.) in the triplestore.
    -   The status of this process can be monitored via the ingestion log endpoint.

Known MTs include `dsg`, `sdd`, `ins` (Instrument), and `str` (Study Response).

### SIR (Semantic Instrument and Response) Elements

SIR elements are used to model scientific instruments, including their hierarchical structure (sections, questions) and coded response options. The API provides dedicated endpoints for creating, querying, and assembling these components.

-   **`instrument`**: The top-level container for a data collection instrument, which could be a survey, questionnaire, or a physical device with sensors and actuators.
-   **`component` / `subcontainer`**: Represents sections or individual questions within an instrument, or logical groupings of detectors/actuators in a physical instrument.
-   **`codebook` / `responseoption`**: Defines the set of possible answers for a question.
-   **`containerslot` / `codebookslot`**: Manages the positioning and attachment of components and response options.

## API Endpoints

The endpoints are grouped by functionality for easier navigation.

### General & Core API

These endpoints provide fundamental operations for retrieving, creating, and managing semantic entities in the repository.

| Endpoint | Method | Path Parameters | Query Parameters | Description |
| --- | --- | --- | --- | --- |
| `/` / `/hascoapi` | `GET`/`POST` | - | - | Renders the main user portal and handles form submissions from it. |
| `/hascoapi/version` | `GET` | - | - | Displays the current version of the HASCOAPI application. |
| `/hascoapi/api/uri/:uri` | `GET` | `:uri` (string) | `email` (string, optional) | Retrieves the full JSON representation of any entity by its unique URI. An optional `email` query parameter can be provided to check and update download permissions for `DataFile` entities. |
| `/hascoapi/api/urigen/:elementtype` | `GET` | `:elementtype` (string) | - | Generates a new, unique, and valid URI for a given `{elementType}`. |
| `/hascoapi/api/usage/:uri` | `GET` | `:uri` (string) | - | Finds and returns all entities that reference or use the entity identified by the given `{uri}`. Useful for impact analysis before deletion. |
| `/hascoapi/api/derivation/:uri` | `GET` | `:uri` (string) | - | Retrieves the provenance and derivation history of the entity, showing how it was generated. |
| `/hascoapi/api/hascotype/:uri` | `GET` | `:uri` (string) | - | Returns the specific HASCO `elementType` for a given entity URI. |
| `/hascoapi/api/children/:superuri` | `GET` | `:superuri` (string) | - | Retrieves the direct children of a given parent element in a hierarchy (e.g., subclasses of a class). |
| `/hascoapi/api/subclasses/keyword/:superuri/:keyword` | `GET` | `:superuri` (string), `:keyword` (string) | - | Searches for and retrieves subclasses of a given parent class (`superuri`) that match a specific `{keyword}`. |
| `/hascoapi/api/superclasses/:uri` | `GET` | `:uri` (string) | - | Retrieves the parent classes of a given entity URI. |
| `/hascoapi/api/instances/keyword/:classuri/:keyword` | `GET` | `:classuri` (string), `:keyword` (string) | - | Retrieves instances of a given class (`classuri`) that match a specific `{keyword}`. |
| `/hascoapi/api/:elementType/create/:json` | `POST`/`GET` | `:elementType` (string), `:json` (string) | - | Creates a new entity of a specific `{elementType}` from a URL-encoded JSON payload. |
| `/hascoapi/api/:elementType/delete/:uri` | `POST`/`GET` | `:elementType` (string), `:uri` (string) | - | Deletes the entity identified by the given `{uri}`. |
